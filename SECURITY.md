# Trendify security: OWASP Top 10:2025 implementation

This maps every measure promised in the SecureStack assignment ("Trendify: Secure
E-Commerce Shopping Website, Application of the OWASP Top 10:2025") to the code that
implements it and the automated test that proves it.

- Backend tests: `cd server && .venv/bin/python -m pytest -q` (100 tests)
- Frontend tests: `cd trendify-frontend && npm test`

Paths are relative to the repository root. `tests/…` means `server/tests/…`.

## A03: Cryptographic Failures

| Measure                                             | Implementation                                                                                                                                                                                  | Verified by                                                                                                       |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| HTTPS/TLS                                           | Enforced at deployment: `FORCE_HTTPS` (default on in production) redirects HTTP and sends HSTS; cookies are `Secure` outside development. TLS itself is terminated by the host or reverse proxy | `server/app.py: enforce_https`                                                                                    |
| Strong password hashing (Argon2)                    | Argon2id via `argon2-cffi` in `server/security.py`. Older Werkzeug hashes still work and are upgraded on the next login                                                                         | `test_register_creates_customer_with_argon2_hash_and_sends_verification`, `test_legacy_werkzeug_hash_is_upgraded` |
| Never store plaintext passwords                     | Only hashes are stored; email/reset tokens are stored as SHA-256 hashes                                                                                                                         | `test_tokens_are_stored_hashed`                                                                                   |
| Encrypt sensitive data where appropriate            | MFA secrets are encrypted at rest with Fernet (AES-128-CBC + HMAC), key from `ENCRYPTION_KEY`                                                                                                   | `test_mfa_enrolment_and_login` (asserts the stored value isn't the secret)                                        |
| Secure session cookies (HttpOnly, Secure, SameSite) | JWTs in `HttpOnly`, `SameSite=Strict`, `Secure` cookies with a CSRF double-submit token; tokens are never in the response body or `localStorage`                                                | `test_login_sets_httponly_strict_cookies_and_no_token_in_body`, `test_mutations_require_csrf_header`              |
| No raw card details                                 | Payment details are entered only on Pesapal's hosted page; Trendify stores the tracking id and status, never card numbers                                                                       | `server/payments.py`                                                                                              |

## A04: Injection

| Measure                               | Implementation                                                                                                                                                      | Verified by                                                                                               |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Parameterized queries / safe ORM      | All database access uses SQLAlchemy expressions; search escapes LIKE wildcards (`escape_like` in `server/api/catalog.py`)                                           | `test_sql_injection_attempts_are_treated_as_text`                                                         |
| Validate input on the server          | Every body and query string goes through a marshmallow schema (`server/validation.py`): types, lengths, ranges, formats, allowed values                             | `test_invalid_query_parameters_are_rejected`, `test_review_input_is_validated`, `test_product_validation` |
| Validate API bodies (mass assignment) | Schemas reject unknown fields, e.g. `{"role": "admin"}` at sign-up or a client-supplied `price`                                                                     | `test_register_rejects_mass_assignment_of_role`, `test_client_supplied_prices_are_rejected`               |
| Encode output (XSS)                   | React escapes all text; there is no `dangerouslySetInnerHTML`. The API only returns JSON                                                                            | `test_review_text_is_stored_verbatim_not_executed`                                                        |
| Don't execute user input              | No `eval`, shell commands or raw SQL built from input. Uploaded images are re-encoded by Pillow, only JPEG/PNG/WebP parsers are allowed, and files get random names | `test_image_upload_is_reencoded`, `test_non_images_are_rejected`, `test_only_jpeg_png_webp_are_parsed`    |
| Content Security Policy               | Frontend build: `script-src 'self'`, `object-src 'none'`, etc. API: `default-src 'none'`                                                                            | `test_security_headers`                                                                                   |
| Open redirect                         | Post-login redirects are limited to same-site paths (`safeRedirect` in `src/lib/api.ts`)                                                                            | `src/test/security.test.ts`                                                                               |

**Accepted risk:** `pillow 12.3.0` has eight advisories fixed only in 13.0.0 (released
2026-10-16). They affect the TIFF, GIF, EPS, PPM and PDF-append code paths. Uploads are
opened with `Image.open(..., formats=["JPEG", "PNG", "WEBP"])`, so those parsers never see
an uploaded file (`test_only_jpeg_png_webp_are_parsed`). CI lists them explicitly; upgrade
to Pillow 13 once it has been out for a couple of weeks and remove the ignores.

## Payment security (section 4 of the assignment)

Pesapal API 3.0 is integrated in `server/payments.py`:

1. Checkout creates the order and calls `SubmitOrderRequest` with the **server-calculated**
   amount; the customer is redirected to Pesapal's hosted page (card, M-Pesa, Airtel Money).
2. Pesapal calls our IPN (`/payments/pesapal/ipn`) and redirects the customer back to
   `/checkout/result`. Neither is trusted on its own.
3. In both cases the server calls `GetTransactionStatus` and only marks the order paid if
   the status is _Completed_ **and** the amount, currency and merchant reference match.
   Mismatches raise a `payment_mismatch` alert.
4. Card and mobile-money details never reach Trendify.

Configure with `PAYMENT_PROVIDER=pesapal`, `PESAPAL_ENV=sandbox|live`,
`PESAPAL_CONSUMER_KEY`, `PESAPAL_CONSUMER_SECRET` and a public `API_PUBLIC_URL` that
Pesapal can reach for the IPN. In local development without credentials,
`PAYMENT_PROVIDER=simulated` (the default for development) shows a test payment page instead.
